# Feature Specification: 계층형 시각 태스크 매니저

**Feature Branch**: `001-visual-task-manager`
**Created**: 2026-07-28
**Status**: Draft
**Input**: "할 일들을 시각적으로 확인해서 관리하는 서비스. 하나의 과업을 여러 개로 쪼갠 구조를 볼 수 있어야 하고, 과업별 / 상태별 / 마감기한별 / 캘린더별로 볼 수 있어야 한다."

---

## 1. 문제 정의

기존 To-Do 리스트는 **모든 할 일을 평평한 목록**으로 다룬다. 이 때문에:

1. "블로그 글 쓰기"(큰 과업)와 "자료 조사 30분"(작은 과업)이 같은 줄에 놓여 무엇이 목표이고 무엇이 수단인지 구분되지 않는다.
2. 큰 과업 하나만 적어두면 실제로 착수할 수 없다. 쪼개는 과정이 필요한데, 쪼갠 결과를 담을 자리가 없다.
3. 여러 과업의 하위 항목들이 뒤섞여 "지금 뭘 해야 하는지"가 보이지 않는다.

이 제품은 **큰 과업 → 작은 과업 2단계 구조를 1급 개념으로 만들고**, 같은 데이터를 네 가지 방식으로 투영해 보여준다.

## 2. 사용자 및 범위

- **1차 사용자**: 본인 (단일 사용자)
- **저장**: 로컬 우선. 로그인하면 서버에 저장되어 기기 간에 동기화된다 (FR-16, 2026-08-16 추가).
- **향후**: 다중 사용자 협업·공유 — 이번 범위에 **포함되지 않음**.
- **기기**: 노트북(데스크톱 브라우저)과 스마트폰(모바일 브라우저) 모두 지원. 네이티브 앱은 범위 밖.

## 3. 핵심 개념 (Ubiquitous Language)

| 용어 | 의미 | 화면 표기 |
|---|---|---|
| **큰 과업 (Project)** | 달성하고자 하는 목표 단위. 그 자체로는 실행할 수 없고 쪼개야 한다. | "큰 과업" |
| **작은 과업 (Task)** | 실제로 착수·완료 체크가 가능한 실행 단위. 반드시 하나의 큰 과업에 속한다. | "할 일" |
| **상태 (Status)** | `To-Do` / `진행 중` / `완료` 세 가지. | 배지 |
| **우선순위 (Priority)** | `높음` / `중간` / `낮음` 세 가지. | 배지 |

계층은 **정확히 2단계**다. 작은 과업은 다시 쪼갤 수 없다.

## 4. 데이터 속성 규칙 (확정)

### 큰 과업
| 속성 | 필수 | 설명 |
|---|---|---|
| 제목 | ✅ | |
| 설명 | ❌ | 자유 텍스트 |
| 상태 | ✅ (기본 To-Do) | **수동 지정.** 하위 완료율에 따라 자동 변경되지 않는다. |
| 우선순위 | ✅ (기본 중간) | |
| 마감일 | ❌ | |
| 색상 | ✅ (자동 배정) | 모든 뷰에서 소속을 식별하는 시각 키 |

### 작은 과업
| 속성 | 필수 | 설명 |
|---|---|---|
| 제목 | ✅ | |
| 메모 | ❌ | |
| 상태 | ✅ (기본 To-Do) | 체크박스로 `완료` 토글 가능 |
| 마감일 | ❌ | |
| 우선순위 | — | **직접 지정하지 않으면 소속 큰 과업의 우선순위를 그대로 따른다.** 사용자가 개별 지정하면 그 값이 우선한다. 지정값은 언제든 "상속으로 되돌리기" 가능. |

> **상속 규칙 (중요)**: 작은 과업이 상속 상태일 때, 큰 과업의 우선순위를 바꾸면 그 작은 과업의 우선순위도 **함께 따라 바뀐다**. 개별 지정된 작은 과업은 영향받지 않는다.

### 파생 값 (저장하지 않고 계산)
- **진행률**: 큰 과업의 `완료된 하위 과업 수 / 전체 하위 과업 수` → `3/7 · 43%`로 표시
- **유효 우선순위**: 작은 과업의 개별 지정값 ?? 소속 큰 과업의 우선순위

## 5. 사용자 시나리오

### US-1. 큰 과업을 쪼갠다 (핵심 시나리오)
사용자가 "포트폴리오 사이트 만들기"라는 큰 과업을 만든다. 그 아래에 "레퍼런스 5개 수집", "와이어프레임 그리기", "메인 페이지 퍼블리싱"을 각각 한 줄씩 추가한다. 세 개의 할 일은 큰 과업 카드 아래 묶여서 보이고, 각각 체크박스로 완료 처리할 수 있다.
- **완료 조건**: 큰 과업 컬럼에서 `+` 한 번 → 제목 입력 → Enter로 할 일이 추가되고, 입력창은 계속 열려 있어 연속 입력이 가능하다.

### US-2. 지금 뭘 해야 하는지 상태로 본다
사용자가 "상태" 탭으로 전환한다. 모든 큰 과업의 할 일이 To-Do / 진행 중 / 완료 세 컬럼으로 재배치된다. 각 카드에는 소속 큰 과업 이름이 색상 배지로 붙어 있어 출처를 알 수 있다. 카드를 다른 컬럼으로 옮기면 상태가 바뀐다.

### US-3. 마감이 급한 순서로 본다
사용자가 "마감기한" 탭으로 전환한다. 할 일이 `지남 / 오늘 / 내일 / 이번 주 / 이후 / 기한 없음 / 끝냄` 그룹으로 나뉜다. **같은 날짜 안에서는 우선순위가 높은 것이 위로 온다.**

### US-4. 달력에서 한 달을 조망한다
사용자가 "캘린더" 탭으로 전환한다. 월간 그리드에 마감일이 있는 항목이 점/막대로 표시된다. 날짜를 누르면 그 날의 항목 목록이 열린다.

### US-5. 폰에서 확인한다
지하철에서 폰으로 접속한다. 컬럼이 세로로 쌓이거나 가로 스크롤되어 읽을 수 있고, 체크박스를 눌러 완료 처리할 수 있다.

### US-6. 데이터를 잃지 않는다
브라우저를 껐다 켜도 데이터가 남아 있다. 메뉴에서 JSON 파일로 내보내고, 다시 불러올 수 있다.

## 6. 기능 요구사항

### FR-1. 큰 과업 관리
- FR-1.1 큰 과업 생성 / 제목·설명·상태·우선순위·마감일 수정 / 삭제
- FR-1.2 삭제 시 하위 할 일이 함께 삭제됨을 경고하고 확인받는다
- FR-1.3 큰 과업의 표시 순서를 변경할 수 있다
- FR-1.4 생성 시 미리 정의된 팔레트에서 색상이 자동 배정되고, 사용자가 바꿀 수 있다

### FR-2. 작은 과업 관리
- FR-2.1 큰 과업 컬럼 안에서 인라인으로 생성 (제목만으로 즉시 생성, Enter 연속 입력)
  - **새 할 일은 목록 맨 위에 쌓인다.** 입력창도 목록 위에 두어 방금 넣은 항목이 바로 아래에 나타나게 한다.
  - 따라서 연속 입력하면 **먼저 적은 것이 아래로 내려간다.** 역산 배치는 화면에 보이는 순서(위 → 아래)를
    작업 순서로 삼으므로, 순서가 중요한 계획이라면 `직접 정한 순서` 로 전환해 드래그로 정리한 뒤 배치한다.
- FR-2.2 체크박스로 완료 ↔ 미완료 토글. 완료 시 취소선 + 흐리게 표시
- FR-2.3 카드를 눌러 상세(제목·메모·상태·마감일·우선순위·소속 변경)를 편집
- FR-2.4 다른 큰 과업으로 이동 가능
- FR-2.5 우선순위는 기본 "상속" 상태이며, 개별 지정 및 상속 복귀가 가능
- FR-2.6 삭제

### FR-3. 뷰
- FR-3.1 **과업별 뷰**: 큰 과업 = 보드 컬럼, 할 일 = 카드. 컬럼 헤더에 상태·우선순위 배지, 마감일, 진행률 바 표시
  - 컬럼 안 정렬은 **마감일 순이 기본**이다. 역산으로 날짜를 정하고 나면 해야 할 차례대로 보여야 하기 때문이다.
    (날짜가 없는 할 일끼리는 우선순위 → 입력 순서로 수렴하므로, 날짜를 정하기 전에는 입력한 순서가 유지된다.)
  - `직접 정한 순서` 로 전환할 수 있다. 마감일 순일 때는 정렬이 순서를 덮어쓰므로 **같은 컬럼 안 재배치 드래그를 받지 않는다**
    (다른 큰 과업으로 옮기는 드래그는 그대로 동작한다).
- FR-3.2 **상태별 뷰**: To-Do / 진행 중 / 완료 3컬럼 칸반. 카드에 소속 큰 과업 색상 배지
- FR-3.3 **마감기한 뷰**: 지남 / 오늘 / 내일 / 이번 주(7일 내) / 이후 / 기한 없음 / **끝냄** 그룹. **정렬 키: 마감일 오름차순 → 우선순위 내림차순 → 큰 과업 순서**
- FR-3.4 **캘린더 뷰**: 월간 그리드. 이전/다음 달 이동, 오늘로 이동. 날짜 칸에 항목 표시, 클릭 시 해당 날짜 상세 패널
- FR-3.5 뷰 전환 시 필터/검색 조건은 유지된다
- FR-3.6 마지막으로 본 뷰를 기억해 다음 방문 시 복원한다

### FR-4. 필터 · 검색
- FR-4.1 제목/메모 텍스트 검색
- FR-4.2 큰 과업으로 필터
- FR-4.3 우선순위로 필터
- FR-4.4 완료 항목 숨기기 토글
- FR-4.5 필터가 걸려 있으면 화면에 명시하고 한 번에 초기화할 수 있다

### FR-5. 조작 방식
- FR-5.1 드래그 앤 드롭으로 카드 이동/정렬 (마우스 + 터치)
- FR-5.2 **드래그로 가능한 모든 동작은 카드 메뉴(⋮)로도 가능해야 한다** (접근성 및 모바일 대비)

### FR-6. 데이터
- FR-6.1 모든 변경은 즉시 로컬에 영속화된다
- FR-6.2 전체 데이터 JSON 내보내기 / 가져오기
- FR-6.3 구조를 이해할 수 있는 샘플 데이터를 제공하고, 한 번에 비울 수 있다.
  단 **자동으로 깔지 않는다** — 사용자가 부를 때만 들어온다 (FR-17)
- FR-6.4 저장 계층은 어댑터 인터페이스 뒤에 있으며, UI는 저장 방식을 알지 못한다

### FR-8. 역산 플래너 (2026-07-28 추가)

> **배경**: 『원씽』식으로 최종 목표에서 거꾸로 짚어 내려와 "오늘 할 일"을 뽑아내는 것이 이 도구의 실제 사용 목적이다.
> 이 흐름에서 날짜는 항목마다 고르는 값이 아니라 **마감일 앵커로부터 도출되는 배분 결과**다.
> 따라서 항목별 날짜 입력을 빠르게 만드는 대신, 배분 자체를 한 번에 하고 시각적으로 조정하게 한다.

- FR-8.1 캘린더 뷰에서 큰 과업을 하나 선택해 계획 대상으로 삼는다. 선택은 전역 과업 필터와 같은 상태를 쓴다.
  - **선택기는 미배치 트레이 안, 목록 바로 위에 둔다.** `계획할 큰 과업` 이라는 라벨을 붙이고 큰 과업만 나열한다.
    (달력 툴바에 떨어뜨려 두면 트레이의 안내 문구와 연결이 보이지 않아, 무엇을 고르라는 것인지 알 수 없다.)
  - 선택된 큰 과업은 달력 툴바에 색상 칩으로, 마감일과 남은 일수는 선택기 바로 아래에 표시한다.
- FR-8.2 마감일이 없는 미완료 할 일을 **미배치 트레이**에 순서대로 모아 보여준다.
  - 트레이는 달력을 스크롤해도 화면에 **고정**되어 드래그 거리를 짧게 유지한다.
  - 창이 낮으면 트레이 전체를 화면 높이에 맞춰 줄이되, `역산 배치` 버튼은 항상 보이고 목록만 안에서 스크롤한다.
- FR-8.3 **역산 배치**: 선택한 큰 과업의 마감일에서 거꾸로, 하위 과업의 순서를 지켜 오늘~마감일 사이에 고르게 배분한다.
  - 첫 항목은 오늘, 마지막 항목은 마감일에 놓인다.
  - **주말도 작업일로 포함한다.**
  - 항목 수가 남은 날보다 많으면 같은 날에 겹쳐 배치된다.
  - 마감일이 오늘이거나 지났으면 전부 오늘에 놓는다.
- FR-8.4 배치 결과는 **미리보기**이며 확정 전까지 저장되지 않는다. 확정 / 취소를 제공한다.
  - 자동 배치는 출발점 제안일 뿐이므로 "정답"처럼 보이게 하지 않는다. 미리보기 항목은 점선으로 구분한다.
- FR-8.5 미리보기 상태에서도, 확정 후에도 항목을 다른 날짜로 **드래그**해 옮길 수 있다. 트레이로 되돌리면 마감일이 지워진다.
- FR-8.6 배치 결과가 화면에 보이는 달을 벗어나면 그 사실과 개수를 알리고 해당 달로 이동할 수단을 준다.
- FR-8.7 역산의 결과물인 "오늘 할 일" 개수를 헤더에 상시 노출하고, 누르면 마감기한 뷰로 이동한다.
- FR-8.9 **확정하지 않은 배치가 있는 상태에서 다른 뷰로 이동하려 하면 저장 여부를 묻는다.**
  - 선택지는 `저장하고 이동` / `저장 안 하고 이동` / `취소` 세 가지다.
  - 탭이든 헤더의 "오늘 N" 칩이든 **모든 뷰 전환은 하나의 통로를 거쳐야** 확인을 빠뜨리지 않는다.
  - 미리보기 상태는 캘린더 뷰의 지역 상태가 아니라 별도 스토어에 둔다(뷰 밖에서도 존재를 알아야 하므로).
    다만 아직 확정하지 않은 값이므로 **영속화하지 않는다** — 새로고침하면 사라진다.
- FR-8.8 큰 과업에 마감일이 없으면 역산할 수 없으므로, 마감일을 먼저 정하도록 안내한다.

### FR-9. 마감일 인라인 편집 (2026-07-28 추가)

- FR-9.1 카드의 마감일 칩을 눌러 그 자리에서 날짜를 바꾼다. 편집 다이얼로그를 열지 않는다.
- FR-9.2 빠른 선택(오늘 / 내일 / 모레 / 다음 주), 직접 날짜 입력, 지우기를 제공한다.
- FR-9.3 마감일이 없는 카드에도 옅은 `📅 날짜` 버튼을 상시 노출해 지정 경로를 만든다.
- FR-9.4 아직 저장하면 안 되는 상황(역산 미리보기)에서는 호출부가 저장 동작을 가로챌 수 있어야 한다.

### FR-7. 표현
- FR-7.1 다크 모드 기본, 라이트 모드 전환 지원 (선택 기억)
- FR-7.2 360px ~ 1920px 반응형
- FR-7.3 한국어 UI, 날짜는 `2025년 5월 23일` 형식

## 6-B. UX 검토 반영 (2026-07-28)

전문가 관점 검토에서 나온 지적 중 아래를 반영한다. 계층 3단계(#5)와 소요 시간/용량(#1)은 이번 범위 밖.

### FR-9. 오늘 뷰가 앱의 현관이다
나머지 네 화면은 "내 일이 어떻게 생겼나"에 답한다. 하루에 열 번 여는 이유인
"지금 뭐 하지"에 답하는 화면이 없어, 헤더에 `오늘 N` 칩을 매다는 우회로가 생겼었다.

- FR-9.1 `오늘` 뷰를 신설하고 **기본 화면**으로 삼는다 (뷰 목록의 첫 번째).
- FR-9.2 구성: `마감 지남` → `오늘 할 일` → `오늘 끝낸 것`. 각 구역 안은 우선순위 순.
- FR-9.3 지난 항목은 죄책감만 쌓지 않도록 **해결 경로와 함께** 보여준다 — `전부 오늘로 옮기기`(되돌리기 가능).
- FR-9.4 오늘 계획이 비어 있으면 다음 행동으로 안내한다 → `역산 배치하러 가기`.
- FR-9.5 오늘 개수는 **탭의 배지**로 표시한다. 헤더 칩은 개수가 0일 때 사라져,
  계획이 가장 필요한 순간에 안내가 없어지는 문제가 있었다.

### FR-10. 되돌리기가 확인 다이얼로그를 대체한다
확인 다이얼로그는 반복되면 읽지 않고 누르게 된다. 되돌릴 수 있는 동작은 묻지 않는다.

| 동작 | 방식 |
|---|---|
| 할 일 삭제 | 즉시 실행 + 되돌리기 (확인 다이얼로그 제거) |
| 캘린더에서 드래그로 마감일 변경 | 즉시 실행, **되돌리기 없음** — 놓은 자리가 곧 결과라 잘못 놓았는지 바로 보이고 다시 끌면 그만이다. 계획을 세우는 동안 연달아 하는 동작이라 매번 토스트가 뜨면 달력만 가린다 |
| 드래그로 큰 과업 이동 · 상태 변경 | 즉시 실행 + 되돌리기 |
| 메뉴로 다른 과업에 이동 | 즉시 실행 + 되돌리기 |
| 지난 항목 전부 오늘로 | 즉시 실행 + 되돌리기 |
| **큰 과업 삭제 · 전부 비우기** | **확인 다이얼로그 유지** (되돌리기로 감당할 규모가 아님) |

- FR-10.1 복구는 `restoreTasks(스냅샷)` 한 경로로만 이뤄진다. 삭제된 것은 되살리고 바뀐 것은 되돌린다.
- FR-10.2 토스트 수명은 10초 — 알아채고 읽고 판단할 시간이 필요하다.
- FR-10.3 **결과가 그 자리에 보이는 동작에는 되돌리기를 붙이지 않는다.**
  되돌리기는 결과를 볼 수 없는 동작을 위한 안전망이다. 캘린더의 날짜 이동, 큰 과업 컬럼 순서 변경이 여기 해당한다.

### FR-11. 접근성 기준선
- FR-11.1 모든 조작 요소의 **터치 타깃은 최소 44×44px**. 보이는 크기는 유지하고 눌리는 영역만 넓힌다(`.tap-44`).
  특히 드래그의 대체 수단인 `⋮` 메뉴가 화면에서 가장 누르기 어려운 요소였다.
- FR-11.2 본문 텍스트는 **WCAG AA 4.5:1** 이상. 가장 작은 글씨에 가장 옅은 색을 쓰던 것을 바로잡는다.
  기준 배경은 가장 밝은 `--surface`.
- FR-11.3 아이콘만으로 전달하던 의미(우선순위 상속 등)에 `sr-only` 텍스트를 함께 둔다.
  툴팁은 터치 기기에서 동작하지 않으므로 유일한 설명 수단이 될 수 없다.

### FR-12. 토글이 아니라 선택지를 보여준다
`⇅ 마감일 순` 같은 토글 버튼은 라벨이 현재 상태인지 누르면 될 상태인지 알 수 없다.
두 선택지를 나란히 놓고 활성 쪽을 강조하는 세그먼티드 컨트롤로 바꾼다.

### FR-13. 하나의 아이콘 언어
이모지(📅🔥⏳💤🚩)와 기하 문자(⚟⤺⇅)가 섞여 있었다. 전부 같은 규격의 선 아이콘으로 통일한다
(16×16, stroke 1.6, currentColor).

- 우선순위는 **방향**으로 표현한다: 높음 ▲ / 중간 – / 낮음 ▼.
  모래시계는 "긴급함"의 기호이지 우선순위가 아니고, 잠은 낮은 우선순위와 은유가 맞지 않았다.
- `⚟` 는 어디에도 필터라는 관습이 없으므로 깔때기로 교체한다.

### FR-14. 큰 과업도 끌어서 순서를 바꾼다
할 일은 카드째 끌 수 있는데 큰 과업 컬럼만 `⋮` 메뉴로 한 칸씩 미는 방식이었다.
같은 화면에서 같은 종류의 조작(순서 정하기)에 두 가지 규칙이 있으면 학습이 이전되지 않는다.

- 컬럼 헤더 왼쪽에 **드래그 손잡이**를 두고, 그 손잡이만 드래그를 시작한다.
  컬럼 전체를 손잡이로 삼으면 카드 드래그·목록 스크롤·헤더 버튼과 전부 충돌한다.
- 컬럼이 하나뿐이면(필터가 걸린 경우 포함) 손잡이를 감춘다 — 할 수 없는 조작은 보이지 않아야 한다.
- 헌법 V에 따라 `⋮` 의 `왼쪽/오른쪽으로 이동`은 그대로 남긴다(키보드·터치 대체 경로).
- **놓기 전에 결과를 보여준다.** 원래 자리는 점선 상자로 남아 드래그하는 동안 계속 목표 위치로 이동한다.
  자리는 **반 칸만 끌면** 열려야 한다. 컬럼을 끄는 동안에는 다른 컬럼만 드롭 후보로 두고
  중심 거리로 판정한다 — 카드까지 후보에 넣으면 옆 컬럼의 카드가 잡히면서
  가로 정렬이 반응하지 않아, 한 칸 옮기려는데 두세 칸을 끌어야 자리가 나타났다.
  결과가 놓기 전에 확정적으로 보이므로 되돌리기 토스트를 두지 않는다(FR-10의 예외).
  되돌리기는 결과를 볼 수 없는 동작을 위한 안전망이지, 볼 수 있는 동작에까지 붙이면 소음이 된다.

### FR-15. 끝낸 일은 아래로 내려간다
목록의 첫 화면은 **아직 해야 할 것**이어야 한다. 완료 항목이 원래 자리에 남아 있으면
남은 일을 보려고 스크롤해야 하고, 목록이 길수록 그 비용이 커진다.

- FR-15.1 과업별 뷰: 컬럼 안에서 완료한 할 일을 맨 아래로 내린다. `마감일 순` · `직접 순서` 양쪽 모두.
- FR-15.2 마감기한 뷰: 완료 항목은 **원래 날짜 그룹에서 빼내** 맨 끝의 `끝냄` 그룹으로 모은다.
  그룹 안에서만 내리는 것으로는 부족하다 — 지난 일을 다 끝냈다면 `지남` 그룹 전체가
  완료 항목으로 채워진 채 화면 맨 위를 차지하고, 정작 오늘 할 일이 그 아래로 밀린다.
- FR-15.3 상태 뷰는 이미 상태가 곧 컬럼이므로 완료 항목이 마지막 컬럼에 따로 모여 있다. 변경 없음.
- FR-15.4 **숨기지는 않는다.** 무엇을 해냈는지 보이는 것에도 값이 있고, 감추고 싶으면
  `완료 숨기기` 필터가 이미 있다. `끝냄` 그룹 제목은 흐리게 처리해 주의를 끌지 않는다.

### FR-16. 기기 간 동기화 (2026-08-16 추가)
노트북에서 만든 일정이 폰에서는 보이지 않았다. localStorage 는 브라우저마다 별개이기 때문이다.
도메인을 붙여도 해결되지 않는다 — 주소가 아니라 **저장 위치**의 문제다.

- FR-16.1 저장소는 Supabase(Postgres). 계정 구분을 위해 **구글 로그인**을 쓴다.
- FR-16.2 **로그인은 선택이다.** 로그인하지 않으면 지금까지처럼 이 기기 안에서 온전히 동작하고,
  환경변수를 설정하지 않은 배포에서는 동기화 메뉴 자체가 나타나지 않는다.
- FR-16.3 서버 어댑터는 `save(전체)` 인터페이스를 유지하되 내부에서 **바뀐 행만** 보낸다.
  통째로 덮어쓰면 "폰에서 체크한 것을 노트북의 열린 탭이 되돌리는" 손실이 실제로 생긴다.
- FR-16.4 충돌은 항목 단위 `updatedAt` 비교로 나중 것이 이긴다.
  로컬과 서버의 병합은 **로그인 순간 한 번**뿐이고, 그 뒤로는 서버가 진실이다
  (삭제는 "사라진 것"과 "아직 안 온 것"을 구분할 수 없어 병합으로 표현할 수 없다).
- FR-16.5 첫 로그인 때 서버가 비어 있으면 그 기기의 데이터를 그대로 올린다 — 데이터를 잃지 않는다.
- FR-16.6 다른 기기의 변경은 realtime 으로 받는다. 다만 **내 변경도 이벤트로 되돌아오므로**,
  이 기기의 쓰기가 잠잠해진 뒤에 서버를 다시 읽는다. 아니면 연달아 입력하는 중에 방금 친 것이 사라져 보인다.
- FR-16.7 데이터 보호는 키가 아니라 **RLS 정책**이 한다. anon 키는 브라우저에 노출되는 것이 정상이다.

### FR-17. 샘플을 자동으로 만들지 않는다 (2026-08-19 추가)
새 기기에서 앱을 처음 열면 샘플이 만들어지고(FR-6.3), 그 상태로 로그인하면
샘플이 "이 기기의 데이터" 로 취급되어 계정에 올라갔다(FR-16.5). 기기를 늘릴수록 샘플이 쌓인다.

처음에는 "손대지 않은 샘플" 이라는 표시를 두고 그것만 걸러냈다. 그러나 **표시가 데이터 전체에 하나뿐**이라,
샘플 상태에서 할 일을 하나만 추가해도 표시가 꺼지고 샘플 전체가 사용자의 것으로 승격됐다.
샘플과 내 데이터가 섞이는 흔한 경로(폰에서 샘플 보고 하나 적어본 뒤 로그인)를 못 막은 것이다.

표시를 항목 단위로 쪼개는 길도 있었지만, 근본 원인은 **샘플이 실제 데이터와 같은 자리에 미리 앉아 있다**는 데 있다.
그 자리에 있는 한 구분은 계속 새로 만들어야 하고 언젠가 또 샌다. 그래서 자동 생성 자체를 없앤다.

- FR-17.1 첫 실행에 샘플을 만들지 않는다. **빈 화면 + 안내**로 시작한다.
- FR-17.2 샘플은 `⋯ → 샘플 데이터 불러오기` 와 빈 화면의 `예시로 둘러보기` 로
  **사용자가 부를 때만** 들어온다. 그건 명시적 선택이므로 계정에 올라가도 놀랍지 않다.
- FR-17.3 빈 화면이 곧 앱의 첫인사다. 큰 과업이 아예 없을 때와 날짜만 안 정했을 때는
  다음 행동이 다르므로 안내도 갈라 놓는다.
- FR-17.4 로그인 결과를 토스트로 알린다 — 불러왔는지·합쳤는지·올렸는지.
  말해주지 않으면 화면이 바뀐 것이 "내 일정이 사라졌다" 로 읽힌다.

### FR-18. 계정은 설정 서랍에 들어가지 않는다 (2026-08-19 추가)
로그인이 `설정 및 데이터` 메뉴 안에 있었다. 발견성과 상태 표시 두 가지가 모두 어긋났다.

- FR-18.1 계정은 툴바 **오른쪽 끝**에 상시 노출한다(거의 모든 앱의 관습).
- FR-18.2 로그아웃 상태에서는 **아이콘이 아니라 `로그인` 글자**로 둔다.
  아이콘만 두면 "무슨 뜻인지 몰라 안 누른다" 는 같은 문제를 되풀이한다.
- FR-18.3 동기화 실패를 계정 버튼에 드러낸다. 실패하면 로컬로 되돌아가는데,
  알리지 않으면 그 기기의 변경이 서버에 가지 않는 상태로 계속 쓰게 된다.
- FR-18.4 `settings` 아이콘을 톱니바퀴로 바꾼다. 기존 아이콘은 원 + 8방향 방사선이라
  `sun` 과 **같은 그림**이었고 실제로 해로 읽혔다. 둘을 가르는 것은 바깥 링이다.
- FR-18.5 아이콘 전용 버튼에 `title` 을 붙인다. `aria-label` 만으로는 마우스 사용자가 알 수 없다.
- FR-18.6 좁은 화면에서는 제목이 줄고 툴바가 온전히 남는다. 반대면 로그인 버튼이 잘린다.

### FR-19. 역산을 설명하지 말고 해보게 한다 (2026-08-19 추가)
캘린더의 역산 배치는 이 도구의 핵심인데, 처음 열면 무엇부터 해야 하는지 보이지 않았다.

튜토리얼(오버레이 안내)을 얹는 길도 있었지만 택하지 않았다. 이유가 셋이다.
**① 역산은 기능이 아니라 일하는 방식**이다 — 버튼 사용법이 아니라 "목표에서 거꾸로 세어 오늘을 정한다"는
습관이라, 읽어서 익혀지지 않고 한 번 해봐야 안다. **② 배우는 시점과 쓰는 시점이 어긋난다** —
정작 역산이 필요한 순간은 마감일 있는 큰 과업을 막 쪼갠 그때인데, 첫 실행 오버레이는 그때 화면에 없다.
**③ 미리보기 패턴이 이미 절반을 하고 있다** — "눌러도 저장되지 않는다"가 보이면 사람은 눌러본다.

- FR-19.1 **라벨이 곧 설명이다.** `역산 배치` 는 결과를 말해주지 않는 추상적인 동사였다.
  남은 일수와 개수를 넣어 `12일에 8개 나누기` 로 바꾼다. 마감일이 지났으면 `N개를 오늘로 모으기`.
- FR-19.2 **누르기 전에 결과를 보여준다.** 버튼에 손을 올리면(호버·포커스) 배치 결과를 달력에 얹어 예고한다.
  예고와 실행이 같은 함수를 쓰므로 어긋날 수 없고, 예고는 저장은 물론 확정 대상도 되지 않는다.
- FR-19.3 **단계에 강약을 준다.** 큰 과업을 고르기 전에는 목록과 버튼을 흐리게 둔다.
  번호를 매기지 않아도 눈이 선택기부터 가고, 화면은 조용하다.
- FR-19.4 **확정이 끝이 아니라 결과를 보는 순간이다.** `오늘 할 일 N개가 잡혔어요` + `오늘 보기`.
  역산이 왜 좋은지는 결과를 봐야 알기 때문이다.
- FR-19.5 도움말은 **접힌 한 줄**로만 둔다 (`거꾸로 잡는다는 게 뭔가요?`).
  "왜"는 한 번은 말해줘야 하지만, 모두에게 강제로 읽히면 아는 사람에게는 소음이다.
- FR-19.6 토스트가 되돌리기 말고 **다음 행동**도 실을 수 있어야 한다.
  되돌리기 버튼을 빌려 쓰면 `실행 취소` 라고 적힌 버튼이 엉뚱한 일을 하게 된다.

### FR-20. 떠 있는 것은 칸에 갇히지 않는다 (2026-08-19 추가)
과업별 뷰에서 카드의 날짜 칩이나 `⋮` 를 누르면 팝오버가 **잘려서** 보였다.
카드 안에 `absolute` 로 그렸는데 컬럼의 할 일 목록이 `overflow-y-auto` 스크롤 영역이라,
그 경계를 넘어가는 부분이 통째로 잘려 나간 것이다. 목록 아래쪽 카드일수록 심했다.

- FR-20.1 메뉴·팝오버는 `document.body` 로 옮겨 `position: fixed` 로 그린다.
  조상의 `overflow` 와 무관해지므로 어느 칸 안에서 열든 잘리지 않는다.
- FR-20.2 대신 위치를 직접 책임진다. 아래 공간이 부족하면 **위로 뒤집고**,
  좌우로 넘치면 화면 안으로 밀어 넣는다.
- FR-20.3 스크롤·리사이즈에 다시 계산해 트리거를 따라간다.
  캡처 단계로 들어야 컬럼처럼 **안쪽에서 스크롤되는** 요소의 이동도 잡힌다.
- FR-20.4 이 처리는 `FloatingLayer` 한 곳에 둔다. 메뉴와 날짜 팝오버가 각자 위치 계산을 들고 있으면
  한쪽만 고쳐진 채로 남는다.

### FR-21. 삭제가 되살아나던 문제 · 올릴지 먼저 묻기 (2026-08-19 추가)

> **증상**: 큰 과업을 지웠는데 다른 기기에 그대로 있고, 앱을 다시 열면 되살아났다.
>
> **원인은 삭제 자체가 아니었다.** 삭제는 누르는 즉시 서버에서 지워진다.
> 문제는 로그인 뒤 **localStorage 가 로그인 시점에 멈춰 있었다는 것**이다.
> 저장 통로가 서버 어댑터로 바뀌면서 로컬 사본이 갱신되지 않았고, 앱을 다시 열면
> `hydrate()` 가 그 낡은 사본을 읽은 뒤 로그인 복원 단계에서 **서버와 합쳐** 버렸다.
> 병합은 삭제를 표현할 수 없으므로(사라진 것과 아직 안 온 것을 구분할 수 없다),
> 지운 항목이 로컬 사본을 통해 매번 되살아나고 서버에도 다시 올라갔다.

- FR-21.1 **합치기는 로그인하는 순간에만 한다.** 앱을 다시 열어 세션이 복원된 경우에는
  서버를 그대로 따른다. 그 시점의 로컬 데이터는 사본이지 별개의 진실이 아니다.
- FR-21.2 방금 로그인한 것인지 그냥 다시 연 것인지는 **로그인 버튼을 누른 시점에 남긴 표시**로 가른다.
  구글에서 돌아오면 세션이 이미 만들어져 있는 경우가 잦아, 시점만으로는 구분되지 않는다.
- FR-21.3 **로그인 직후, 이 기기에 데이터가 있으면 올릴지 먼저 묻는다.**
  묻지 않고 합치면 계정에 없어야 할 것이 조용히 올라간다.
  - `올리고 동기화 시작` — 계정 데이터와 합친다.
  - `나중에 — 먼저 정리할게요` — **아무것도 올리지도 내려받지도 않고 멈춘다.**
    이 기기에서 정리를 마친 뒤 계정 메뉴의 `지금 올리고 동기화 시작` 으로 이어서 하면 된다.
    이 대기 상태는 계정 버튼에 `동기화 대기` 로 드러난다 — 보이지 않으면
    "로그인했는데 왜 동기화가 안 되지" 로 남는다.
- FR-21.4 로그인 상태에서도 **localStorage 를 함께 갱신한다**(서버 저장이 성공한 내용만).
  낡은 사본이 남지 않고, 오프라인에서 첫 화면을 그릴 캐시가 된다.

> **남는 한계**: 로그인한 채 오프라인에서 편집한 내용은 큐에 쌓이지 않는다.
> 서버 저장이 실패하면 그 변경은 유실되고, 다음 실행 시 서버 상태를 따른다.

## 7. 비기능 요구사항

- **NFR-1 성능**: 큰 과업 30개 / 할 일 500개 기준으로 뷰 전환이 즉각적일 것
- **NFR-2 오프라인**: 네트워크 없이 동작 (로컬 저장이므로 자연히 충족)
- **NFR-3 데이터 안전성**: 스키마에 버전 필드를 두어 향후 마이그레이션이 가능할 것
- **NFR-4 확장성**: 서버 백엔드 도입 시 UI 컴포넌트 수정 없이 어댑터 교체로 대응

## 8. 이번 범위에서 제외

- 로그인/회원가입, 다중 사용자, 협업·공유, 댓글

- 3단계 이상 계층

- 하위 완료율에 따른 큰 과업 상태 자동 전환 (수동 지정으로 확정)
- 시간 단위 스케줄링(주간 타임그리드)

## 9. 인수 기준 (Acceptance Criteria)

| # | 시나리오 | 기대 결과 |
|---|---|---|
| AC-1 | 큰 과업 생성 후 할 일 3개 추가 | 컬럼 아래 3개 카드, 헤더에 `0/3 · 0%` |
| AC-2 | 그중 1개 체크 | 즉시 `1/3 · 33%`, 카드 취소선 |
| AC-3 | 상태 탭 전환 | 방금 체크한 항목이 "완료" 컬럼에, 나머지는 "To-Do"에, 모두 소속 배지 표시 |
| AC-4 | 큰 과업 우선순위를 "높음"으로 변경 | 개별 지정하지 않은 하위 할 일 전부가 "높음"으로 표시 |
| AC-5 | 할 일 하나만 "낮음"으로 개별 지정 후 큰 과업을 "중간"으로 변경 | 그 할 일만 "낮음" 유지 |
| AC-6 | 같은 마감일에 우선순위가 다른 항목 2개 | 마감기한 뷰에서 높음이 위 |
| AC-7 | 마감일이 있는 항목 생성 후 캘린더 탭 | 해당 날짜 칸에 항목 표시, 클릭 시 상세 |
| AC-8 | 브라우저 새로고침 | 모든 데이터와 마지막 뷰 유지 |
| AC-9 | 375px 폭 | 가로 스크롤 없이 모든 뷰 사용 가능, 체크 동작 |
| AC-10 | 내보내기 → 데이터 비우기 → 가져오기 | 원래 상태로 복원 |
| AC-11 | 마감일 12일 뒤인 큰 과업 + 미배치 할 일 8개 → 역산 배치 | 첫 항목 오늘, 마지막 항목 마감일, 순서 유지, 주말 포함 |
| AC-12 | 미리보기 상태에서 항목 하나를 다른 날로 드래그 후 확정 | 조정한 날짜까지 그대로 저장됨. 확정 전에는 저장되지 않음 |
| AC-13 | 배치된 항목을 트레이로 드래그 | 마감일이 지워지고 트레이로 돌아옴 |
| AC-14 | 카드의 날짜 칩 클릭 → "오늘" | 다이얼로그 없이 마감일이 오늘로 저장되고 헤더 "오늘 N" 갱신 |
| AC-15 | 과업별 뷰에서 첫 컬럼의 손잡이를 세 번째 컬럼 위로 드래그 | 끄는 동안 놓일 자리가 점선 상자로 보이고, 놓으면 그 자리에 그대로 저장 |
| AC-16 | 컬럼 순서 변경 기능 추가 후 카드를 다른 컬럼으로 드래그 | 기존대로 소속이 바뀌고 되돌리기 토스트가 뜬다 (회귀 없음) |
| AC-17 | 완료한 할 일이 섞여 있는 큰 과업 컬럼 | `마감일 순`·`직접 순서` 모두에서 완료 항목이 목록 맨 아래 |
| AC-18 | 지난 항목을 전부 완료 처리한 뒤 마감기한 뷰 | `지남` 그룹이 사라지고 화면 맨 위가 `오늘`, 완료 항목은 맨 끝 `끝냄` 그룹 |
| AC-19 | 마감기한 뷰에서 할 일을 체크 | 그 자리에서 사라지고 `끝냄` 그룹 맨 아래에 나타난다 |
| AC-20 | 환경변수를 설정하지 않은 상태 | 동기화 메뉴가 없고 앱은 로컬 전용으로 종전과 동일하게 동작 |
| AC-21 | 데이터가 있는 노트북에서 첫 로그인 | 그 데이터가 서버에 그대로 올라간다 |
| AC-22 | 폰에서 같은 계정으로 로그인 | 같은 일정이 나타난다 |
| AC-23 | 노트북에서 항목 체크 | 폰 화면에 새로고침 없이 반영된다 |
| AC-24 | 로그아웃 | 화면의 데이터는 유지되고 이 기기의 localStorage 에 남는다 |
| AC-25 | 새 기기에서 앱을 처음 열기 | 샘플이 생기지 않고 빈 화면 + `첫 큰 과업 만들기` · `예시로 둘러보기` |
| AC-28 | 샘플을 불러온 뒤 할 일을 추가하고 로그인 | 명시적으로 부른 샘플이므로 함께 올라간다 (예상된 동작) |
| AC-29 | 마감 12일 남은 큰 과업 + 미배치 3개 선택 | 버튼 라벨이 `12일에 3개 나누기` |
| AC-30 | 그 버튼에 마우스를 올림 | 달력에 결과가 예고되고, 저장소·미리보기 상태는 그대로 |
| AC-31 | 큰 과업을 고르기 전 | 목록과 버튼이 흐리게 표시된다 |
| AC-32 | 배치 후 확정 | `오늘 할 일 N개가 잡혔어요` + `오늘 보기` 로 결과를 확인하러 갈 수 있다 |
| AC-33 | 스크롤되는 컬럼의 **맨 아래** 카드에서 날짜 칩·`⋮` 열기 | 잘리지 않고 전체가 보이며, 아래 공간이 없으면 위로 뒤집힌다 |
| AC-34 | 팝오버를 연 채 컬럼을 스크롤 | 트리거를 따라 위치가 갱신된다 |
| AC-35 | 375px 에서 팝오버 열기 | 좌우로 넘치지 않고 화면 안에 들어온다 |
| AC-36 | 기기 A 에서 큰 과업 삭제 → 앱 재시작 | 되살아나지 않는다 |
| AC-37 | 기기 A 에서 삭제 → 기기 B 새로고침 | 기기 B 에서도 사라진다 |
| AC-38 | 데이터가 있는 기기에서 로그인 | 올릴지 먼저 묻는다 |
| AC-39 | 그 물음에 `나중에` | 아무것도 올라가지 않고, 계정 버튼이 `동기화 대기` 로 바뀐다 |
| AC-40 | 정리 후 `지금 올리고 동기화 시작` | 그때 합쳐지고 동기화가 시작된다 |
| AC-26 | 로그인 직후 | 무슨 일이 있었는지 토스트로 알려준다 |
| AC-27 | 375px 로그아웃 상태 | `로그인` 버튼이 잘리지 않고 제목이 줄어든다 |
