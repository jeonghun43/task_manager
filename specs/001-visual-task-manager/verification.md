**고치면서 발견한 것**: `aside` 에 `self-start` 를 주면 콘텐츠 높이만큼만 차지해,

`items-start` 를 걷어내 aside 가 달력 높이만큼 늘어나게 하니 해결됐다.

**설계 메모**: 미리보기를 캘린더 뷰의 지역 상태로 두면 뷰가 언마운트되며 조용히 사라진다.
스토어로 올려 뷰 밖에서도 존재를 알 수 있게 했고, 뷰 전환을 `AppShell.requestView` 하나로 모아
탭·헤더 칩 어느 쪽으로 나가도 확인을 빠뜨리지 않게 했다.
다만 미리보기는 확정 전 값이므로 영속화하지 않는다 — 새로고침하면 사라진다.

### 검증 방법에 대한 메모

드래그 검증 시 이동과 드롭을 같은 tick 에 보내면 React 가 리렌더할 틈이 없어 `over` 가 갱신되지 않는다.
이 때문에 처음 두 번은 드롭이 실패한 것처럼 보였으나 앱의 결함이 아니라 테스트 방식의 문제였다.
이동과 드롭을 분리하니 정상 동작했다.

또한 콘솔 메시지 버퍼는 새로고침해도 비워지지 않는다.
1차 검증의 "콘솔 오류 0건" 은 버퍼가 비어 있던 시점의 관측이었고,
실제로는 당시 인라인 스크립트 경고가 있었다. 새 탭에서 다시 확인해 현재는 오류 0건임을 확인했다.

**검증 도중의 함정 두 가지 (앱 버그 아님)**
- 합성 `mouseover`/`focus` 이벤트는 React 의 합성 이벤트 체계에 닿지 않아 예고가 뜨지 않았다.
  브라우저 도구의 실제 커서 `hover` 로 바꾸자 정상 동작했다.
- 토스트 수명이 10초라, 클릭과 확인 사이에 도구 호출이 여러 번 끼면 이미 사라진 뒤였다.
  같은 호출 안에서 클릭 → 대기 → 확인으로 묶어야 잡힌다.
